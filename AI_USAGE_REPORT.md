# AI Usage Report — SmartSchedule

This document details the usage of AI coding assistance during the design, implementation, and verification of **SmartSchedule — Intelligent College Timetable Generator**.

---

## 1. AI TOOL USED
- **Tool**: Google Antigravity / Gemini 3.8 Flash (High) Agentic Coding Assistant
- **Development Environment**: Node.js v24, Windows PowerShell, Vite, React 18, Tailwind CSS, Mongoose

---

## 2. WHAT I ASKED AI TO DO
1. **Architecture & Scaffolding**:
   - Establish a clean, modular MERN project layout separated into `backend/` and `frontend/`.
   - Setup environment variable placeholders strictly guarding credentials without hardcoded URIs.
2. **Core Constraint Engine**:
   - Design and implement a pure JavaScript Constraint Satisfaction Problem (CSP) solver incorporating:
     - Backtracking search with Forward Checking.
     - Minimum Remaining Values (MRV) and Degree Heuristics (Difficult-First scheduling).
     - Multi-period practical lab contiguous block integrity.
     - In-depth, grounded failure diagnosis for impossible constraint scenarios.
     - Iterative local search soft constraint optimization.
3. **Mongoose Schemas & API Suite**:
   - Implement Mongoose models for Users, Departments, Divisions, Faculty, Subjects, Classrooms, TimeSlots, Timetables, and GenerationLogs.
   - Build RESTful controllers with role-based JWT authentication, validation, and cascade safety.
4. **Professional React Frontend**:
   - Create a dashboard with 8 KPI metrics, conflict warning alerts, and recent runs.
   - Build CRUD management interfaces with interactive availability matrices for faculty and rooms.
   - Develop the master Timetable Grid supporting Division, Faculty, and Classroom view modes, CSV export, and print formatting.
   - Implement the "Why This Timetable?" algorithmic proof modal and dedicated Conflict Center.
5. **Testing Suite**:
   - Author 15 automated unit and integration tests covering all 8 hard constraints, backtracking, impossible scenario diagnosis, and optimization.

## 3. PROMPT THAT WAS MOST USEFUL
> *"The most important part of this project is NOT simple CRUD. The most important part is the intelligent constraint-based timetable generation engine... Build a genuine constraint-based timetable generator. DO NOT randomly generate timetable entries. DO NOT hardcode a timetable. DO NOT simply shuffle subjects. If a timetable cannot be generated, do NOT show only: 'Generation failed.' Provide Problem, Affected division, Subject, Faculty, Required room, Relevant day/period, Reason, and Suggested resolution derived from actual constraint checks."*

It directed focus squarely onto algorithmic correctness, domain modeling, and informative diagnostics rather than superficial UI features.

## 6. AI OUTPUT THAT WAS WRONG / SUB-OPTIMAL
- **Initial Task Ordering**:
  - Initially, the model proposed scheduling single-period theory subjects before 2-period laboratory blocks.
- **Failure Feedback**:
  - Early prompts generated generic error strings like "Backtracking failed to find a valid assignment" without identifying the exact bottleneck resource.

---

## 7. HOW I IDENTIFIED THE PROBLEM
- Running the scheduler with high constraint contention (such as only 2 qualifying laboratory slots for 3 divisions) revealed that early theory assignments consumed prime morning slots, leaving no contiguous 2-period blocks for laboratories and causing immediate backtracking failure.

---

## 8. HOW I FIXED IT
- Implemented the **Difficult-First Heuristic** in `helpers.js`:
  1. Multi-period laboratory sessions are ordered first.
  2. Tasks with the fewest qualifying rooms (MRV) are scheduled before flexible theory subjects.
  3. Tasks with fewer eligible faculty members are prioritized.
- Created `diagnoseSchedulingFailure()` in `generator.js` to cross-examine required lab slots against available room-hours and division student capacity, pinpointing the exact failure cause.
